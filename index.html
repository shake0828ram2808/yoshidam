Works

業務の中で取り組んだ、開発体験を良くするための工夫です。

Case 01

マルチリポジトリからモノレポへ

  • pnpm workspaces
  • CI共通化
  • 依存管理
課題
フロントエンド資産が複数のリポジトリに分かれ、同じ修正を何度も入れる・バージョンがずれる状態だった。
やったこと
モノレポ構成に統合し、依存関係を一元管理。CIの設定を共通化した。
結果
リリースまでの手間が減り、リリースサイクルを短縮できた。

リリース頻度(月あたり)

Before
2回
After
6回
なぜモノレポを選んだか

ほかの選択肢(共通パッケージを別リポジトリで公開する、git submodule など)と比べ、変更が1つのPRで完結し、レビューしやすい点を重視した。

Case 02

npm から pnpm への移行

  • pnpm
  • CI高速化
  • 移行計画
課題
node_modules が肥大化し、インストールとCIに時間がかかっていた。
やったこと
pnpmへ移行し、ワークスペースの設計を見直した。移行手順を段階に分けて、影響範囲を小さく保った。
結果
CIの実行時間とディスク使用量を削減できた。

CI 実行時間

Before
12分
After
7分
ハマったところ

幽霊依存(package.json に書かれていないのに動いていた依存)が表に出たので、ひとつずつ明示的に追加して解消した。

Case 03

AI駆動開発への挑戦

  • Claude Code
  • 開発フロー設計
  • チーム導入
課題
AIツールを個人では使っていても、チームの開発フローには組み込めていなかった。
やったこと
Claude Codeをチーム開発に取り入れ、設計レビューや実装の一部を任せるフローを構築した。
結果
導入の壁と、実際に効果のあった使い方をチームで共有できる形にまとめた。
個人開発での使い方

リポジトリごとに CLAUDE.md で設計方針・編集ルール・確認手順を書き、方針決定は自分、確定した実装はAIに任せる、という役割分担で開発している。
