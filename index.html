    05

    How I Build

    個人開発は、AIと役割を分けながら進めています。
    「どう作っているか」も、見てもらえるとうれしいです。

    AI駆動開発のサイクル

    1. 1

      ルールを書く

      リポジトリごとに CLAUDE.md を置き、目的・守ること・確認の手順を書く。

    2. 2

      役割を分ける

      方針や設計の判断は自分。仕様が決まった実装や単純作業はAIに任せる。

    3. 3

      自動で確かめる

      単体テストと、スマホサイズのスクリーンショット(Playwright)で確認する。

    4. 4

      実機で触る

      実機で遊び、気になるところはスクショに印をつけて伝える。

    5. 5

      記録して、くり返す

      変更履歴と資料を毎回更新。次の会話でもAIが経緯をたどれる。

    設計の見どころ

    • 保存先を差し替えられる設計。保存処理をリポジトリ層にまとめ、Web と iOS で実装だけを切り替える。
    • 計算ロジックは必ずテスト。服薬日数のカウントなど 18ファイル・143件の単体テスト(Vitest)。
    • 健康データは端末の外に出さない。天気APIに送る位置情報も、地域程度に丸める。
    • 仲間との共有はサーバー側でも検証。Cloudflare Workers + D1。パスワードは PBKDF2 でハッシュ化。
    • ライブラリなしの自作エンジン。素の JavaScript と Python の自作ビルドで、1枚の HTML に結合。
    • 音はすべてコードで生成。効果音36種を WebAudio で合成し、音声ファイルは0。BGMはストリーミング再生。
    • 文言は1つの表から。TEXT.md の表をビルド時に読み込み、日本語/ひらがなを切り替え。
    • 素材づくりも自動化。画像生成から背景の切り抜き、組み込みまでをスクリプトで。
    • キャラは共通ライブラリに。ピコのSVG・アニメーション・口パク・吹き出しを shared/piko.js にまとめた。
    • シリーズで使い回す。けいさん・くく・めくって の3本を iOS で配信。くくで作ったキャラの部品を めくって でも使い、共通ライブラリへ集約中。
    • ビルドで1ファイルに。共通部分はビルド時に埋め込み、Capacitor で iOS アプリ化。

    開発ログ: だんごむしのぼうけん

    改善リリースv155

    遊んでみて気づいたことを、すぐ直す。その積み重ねの主な節目です。

    1. v1はじまりチャットで作った試作を、アプリの骨組み(モック)に移した
    2. v37操作が決まるやじるしスティックで歩き、手をはなすと丸まる操作に決定
    3. v39絵本のマップぼうけんマップを、1エリア=1ページの絵本式に
    4. v70ソースを分割CSS / JS / 骨組みに分け、ビルドで1枚のHTMLに結合
    5. v85137KBに画像を配信用フォルダへ書き出し、ページを 17MB → 約137KB に
    6. v108遊びの深み星3つの評価と、ボスを枝に「はめる」パズルを追加
    7. v123音をコードで効果音36種を WebAudio で生成。音声ファイルは0
    8. v129文言を1つの表に全テキストを表に集約し、日本語/ひらがなを切り替え可能に
    9. v139チュートリアル操作を1つずつ教え、できたら ほめる
    10. v148新しい敵たちアリジゴク・つむじ風・カエル。それぞれ違う避け方
